Complete Phase 1 of the feedback widget implementation: API service, routes, and screenshot upload (Steps 1.3 and 1.4).

## What Was Done

### Step 1.3: Feedback API Service & Routes (commit 693dceb)

- Created `apps/api/src/services/feedback.service.ts` — full CRUD with admin notifications
  - `createFeedback()` — saves to DB, notifies all admins via in-app notification + email
  - `getFeedbacks()` — paginated list with status filter (admin only)
  - `updateFeedbackStatus()` — change feedback status (admin only)
  - `deleteFeedback()` — remove feedback (admin only)
  - HTML-escaped user content in email templates (XSS prevention)
- Created `apps/api/src/routes/feedback.ts` — Express routes with middleware
  - `POST /api/feedback` — any authenticated user, custom rate limit (10/hr/user)
  - `GET /api/feedback` — admin only, `validateQuery()` middleware for proper 400 errors
  - `PATCH /api/feedback/:id` — admin only, status update
  - `DELETE /api/feedback/:id` — admin only
- Registered route in `routes/index.ts` and `app.ts` `registerRemainingRoutes()`

### Step 1.4: Screenshot Upload Endpoint (commit 9ea02c5)

- Added `uploadScreenshot()` to `feedback.service.ts`
  - Base64 decode → validate minimum buffer size (4 bytes) → validate max size (5MB) → validate PNG/JPEG magic bytes → upload to S3 under `feedback-screenshots/` prefix
- Added `POST /api/feedback/upload-screenshot` route (auth required, no rate limiter to avoid double-counting with submission)

### Documented (Not Fixed)

## Key Decisions

| #   | Decision                   | Choice                                               | Rationale                                                                 |
| --- | -------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| 1   | Rate limiter scope         | Only on `POST /api/feedback` (submit), not on upload | Prevents double-counting; upload is a helper, submit is the atomic action |
| 2   | Email notification pattern | Fire-and-forget with `.catch()`                      | Email failures are non-critical; don't block feedback creation            |
| 3   | Query validation           | `validateQuery()` middleware                         | Matches existing codebase pattern (notifications, articles, etc.)         |
